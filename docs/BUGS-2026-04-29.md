# Bugs — 2026-04-29

## Bug 1: Volume data corruption (5 sub-bugs, all FIXED)

### 1A: Index VWAP always using zero volume
**File:** `backend/app/services/strategy_runner.py:1131-1139`
**Status:** FIXED
**Root cause:** `if sum(volumes) == 0` condition was too strict — sporadic non-zero volume spikes (~9% of candles) from reconnect transients prevented the futures fallback from triggering. Changed to `if symbol in self._index_futures_info:` to always use futures volume for indices.

### 1B: WS reconnect dumps cumulative day volume into single candle
**File:** `backend/app/data_feed/feed_manager.py:232-244`
**Status:** FIXED
**Root cause:** `clear_in_progress_candles()` was clearing `_last_vol_today` baselines on WS disconnect. First post-reconnect tick computes `delta = cumulative - 0 = entire day's volume`. Removed `_last_vol_today.clear()`.

### 1B+: VWAP RuntimeWarning (division by zero)
**File:** `backend/app/indicators/vwap.py:45-53`
**Status:** FIXED
**Root cause:** `np.where(mask, x/y, 0)` evaluates both branches before masking. Changed to `np.divide(..., out=np.zeros_like(...), where=mask)`.

### 1C: Historical data corruption (Apr 17-24)
**Status:** FIXED (DB cleaned)
**Root cause:** Pre-Apr-24 code had no volume delta logic — every tick stored cumulative `vol_traded_today`. Sub-second timestamps bypassed the unique constraint, creating duplicate rows. DB cleanup: deleted 40,813 duplicates, normalized 12,878 orphans, zeroed inflated volumes. Verified all symbol+date combos now within 100-120% of daily reference.

### 1C+: DISTINCT ON dedup picked wrong row
**Files:** `strategy_runner.py:1000`, `context_builder.py:140`
**Status:** FIXED
**Root cause:** `ORDER BY volume DESC` in DISTINCT ON picked inflated cumulative-volume rows over correct backfill rows. Changed to `ORDER BY timestamp` (earliest = backfill).

## Bug 2: Nifty CE SL/Target wrong (DEFAULT_SL_PCT = 30.0)
**Status:** FIXED
**Root cause:** `DEFAULT_SL_PCT = 30.0` should be `0.30` (fraction, not percentage). The fallback path in `option_resolver._compute_premium_sl_target` computes `sl_price = premium * (1 - 30.0) = -5853.57`.
**Fixes applied:**
1. `constants.py:101` — `DEFAULT_SL_PCT = 0.30`
2. `strategy_params.py` — Replaced dead `default_sl_pct` key with `sl_pct_aligned: 0.30` / `sl_pct_unaligned: 0.35` (configurable per bias direction)
3. `strategy_2_vwap_pullback.py:180-188` — Reads new direction-aware SL params instead of hardcoded `+0.05` bump
4. `option_resolver.py:380-384` — Added validation guard: if `sl_pct >= 1.0`, logs error and clamps to 0.30
5. DB: Fixed corrupted trade/position, renamed `sl_pct_bullish`/`sl_pct_neutral` → `sl_pct_aligned`/`sl_pct_unaligned` in strategy_configs parameters
